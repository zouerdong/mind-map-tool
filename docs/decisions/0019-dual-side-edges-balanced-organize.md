# ADR 0019：双侧连线与「发散」整理方向

- Status: Accepted
- ADR-Version: 1.1.0
- Date: 2026-09-18（v1.1.0 修订 2026-09-20）
- Deciders: 项目负责人（2026-09-18 内测反馈批次定稿：Q2 选 B——「左边除了能接进来线，也能拉出去线，通过箭头是可以看出去处和来处的」；2026-09-20 v0.3.1 dogfood 反馈定稿 v1.1.0 三项修订）/ 主会话（工程实现）
- 任务来源: 2026-09-18 内测反馈：同级 idea 框很多时，一键整理横向过宽或纵向过长；同事提议两侧均可出线，配合箭头即可支撑「根居中、向两边发散」的排版。

## Context

G-VIS D7 冻结契约为「整理默认横向，右出左入」：`mind-node` 只渲染 target=左、source=右
两个 handle；`edge-geometry.ts` 的路由（comb/channel/turn）以「源在左、目标在右」为隐含前提；
`organize.ts` 的分层方向只有 horizontal / vertical 两种。同级节点多时只能排成一行/一列，
观感问题在内测中被多人指出。边的箭头已明确表达流向，方向语义不依赖锚点侧。

## Decision

1. **双侧连线**：每个节点左右两侧均既能进线也能出线。schema 不变——边仍只记录
   source/target 节点 id，**不持久化 handle 侧**；锚点侧由投影层按两端节点相对几何确定性
   派生（目标中心在源中心左侧 → 左出右入，反之右出左入；重叠/平局按文档序与坐标确定性
   规则裁决），导出经同一几何派生自动跟随，无文件格式迁移。
2. **整理新增第三方向 `balanced`（发散）**：横向 / 纵向 / 发散三选，入口随现有方向切换
   （菜单）；~~横向仍是默认值，存量文档行为不变~~（v1.1.0 起发散为默认，见文末修订）。
   发散规则：主图主根
   （缩点 DAG 入度 0 分量中文档序最小者）居中，其第一层子树按子图体量交替分配到左右
   两侧做贪心平衡，左支整体镜像布线；多父/跨层/环/孤立节点沿用既有降级规则
   （不转单父树、不删边），无法明确归属单侧的子图回退右侧横向排布。确定性要求与
   现有横向/纵向一致（只依赖节点/边集合与文档序）。
3. **修订 G-VIS D7**：默认横向「右出左入」不变；发散方向下左支镜像为「左出右入」，
   箭头始终指向 target，流向表达不依赖锚点侧。

## Amendment v1.1.0（2026-09-20，项目负责人批准）

v0.3.1 macOS dogfood 反馈：同级 idea 卡很多时点整理仍挤成一列——用户从未发现「发散」
方向（默认横向 + 入口在原生菜单勾选）。两轮内测均踩同一默认值的证据充分，负责人
2026-09-20 批准以下三项一并修订：

1. **默认方向改为 `balanced`（发散）**：横向/纵向保留为可选；预发布阶段无存量兼容
   负担，「存量文档行为不变」条款自此作废。`organize()` 缺省方向、UI 缺省状态、
   原生菜单初始勾选同步改为发散。
2. **发散布局增加主根垂直居中**：v1.0.0 各列一律自 y=0 堆叠，主根停在顶部呈 T 形。
   修订后：左支块、右支块、主根列分别计算各自总高，三者对最大高度垂直居中
   （各块内部相对几何不变，只加整块偏移；偏移量 ≥0，不产生负坐标）。确定性口径
   不变（只依赖节点/边集合与文档序）。
3. **方向记忆更正为「应用级偏好」**：v1.0.0 原文「随文档记忆」与 ADR 0003 冲突
   （偏好绝不写入脑图文档；文档 schema 无 preferences 字段，改动需走文件格式 Gate）。
   方向是「整理命令的调用偏好」而非文档内容——整理结果坐标已落盘，方向本身不影响
   文档数据。实现为 MM-060 PreferencesPort 持久化 `layoutDirection` 键，启动时读取，
   三向命令切换时写入；非法/缺失值回退默认（发散）。

## Consequences

### Positive

- 同级大量节点可整理为根居中、两侧发散的紧凑排版，直接回应内测主诉；
- 手动连线更自由，符合白板类工具直觉；
- 锚点侧派生不落 schema，既有 v1 文件零迁移。

### Negative

- `edge-geometry.ts` 路由须支持左出/镜像（comb/channel/turn 三策略均需覆盖），
  整理动效的插值路径同步适配；
- 导出 golden（SVG/PNG/PDF）涉及边几何的用例需按 REGEN 流程重基线；
- 键盘连线流与方向导航需兼容双侧锚点；横向整理下「左拉边」成为回退边，
  由 channel 路由兜底，需专项测试；
- 发散模式的平衡分配规则是新的确定性契约，需在 organize 注释与测试中锁定。

## Validation

- `organize` 发散方向单元测试：同输入同输出、单命令可撤销、超限结构化失败；
- 边几何：整理后零共线重叠检测（复用 findCollinearOverlaps）覆盖发散与回退边用例；
- 三格式导出 golden 重基线后 `pnpm quality` 全绿；
- 内测 dogfood：同级 12+ 节点的文档在三种方向下整理观感对比（负责人验收）。
