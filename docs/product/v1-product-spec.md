## 1. 产品结论

第一版是一款 **macOS 优先**的本地桌面应用（[from-user] 2026-08-26 范围变更：v1 以 macOS 为发布平台，Windows 作为稳定后的专门版本跟进，但架构必须保留 Windows 转换口）。启动后立即呈现可平移、缩放的空白自由画布，用户在任意位置创建文字节点、移动节点并自由连接，以最低操作负担外化思路。

它不是传统树状自动布局脑图，也不是云白板。第一版没有服务器后端、账号、同步、协作、AI 或富媒体节点。

### 1.1 平台范围与移植就绪（[from-user] G1 决定）

- **v1 发布平台：macOS（Apple Silicon）**。Intel Mac 是否覆盖暂不承诺。
- **Windows：后续专门版本**，不属于 v1 验收范围；v1 不需要在 Windows 上运行。
- **移植就绪约束（强制）**：`packages/core` 与 `packages/ui` 不得引入 macOS 专属 API；所有平台能力（文件、对话框、生命周期、快捷键差异）只存在于 `packages/platform` 的 port 之后；Tauri 配置保持跨平台结构（不硬编码 macOS-only 路径）；文件 schema 与导出管线平台无关。违反即视为范围回归。


## 2. 用户问题与产品目标

### 2.1 核心用户

- 首要用户：[from-user] 随时需要整理关联性想法的创意工作者。
- 次要用户：希望用免费、本地、无账号工具进行自由空间思考的个人用户。
- 第一阶段真实使用范围：[from-user] 用户自己的 macOS 与 Windows 设备；验证通过后才准备 GitHub 公开分发。

### 2.2 要解决的问题

现有产品很难同时满足免费、本地、无需账号、极简、轻量与双平台。用户真正需要的是“念头出现后立即进入思考”，而不是维护一套复杂的图表、云文档或付费订阅工作流。

### 2.3 成功结果

用户从启动到创建第一个可编辑节点无需经过登录、模板选择或项目管理页；可以只凭鼠标完成建图闭环，并通过快捷键加速高频动作；保存后的原生文件可以再次打开；同一内容可导出 SVG、2x PNG 和 PDF。

## 3. 设计原则

1. **空白画布先于工具界面**：应用图标或 Dock 激活意图必须创建新空白文档；若应用已运行则新建空白窗口，不能替换或破坏已有 dirty 文档。只有双平台 Spike 证明某一入口无法可靠实现时，才可作为范围变更重新请求用户决定。
2. **自由关联先于树形结构**：节点可放置在任意坐标，连接不表达强制层级。
3. **本地文件是数据主权边界**：保存、打开、文件关联都围绕用户选择的本地文件，不引入账号、云或遥测。
4. **少而完整**：第一版只保留能完成“创建—连接—整理—保存/导出—再次打开”的能力。
5. **跨平台一致、差异显式**：macOS 与 Windows 的快捷键修饰键、文件打开事件和打包差异只出现在平台适配层。

## 4. 核心用户旅程

### 4.1 从应用图标开始

1. 用户点击应用图标或触发 Dock 激活。
2. 应用显示一个新的空白画布；不得恢复上次明确放弃的未保存会话。
3. 首次使用时，用户可进入交互式引导，也可跳过。
4. 用户在画布任意位置创建文字节点并直接输入。
5. 用户创建更多节点，移动位置并连接相关想法。
6. 用户可撤销/重做错误操作，切换白板/黑板主题。
7. 用户主动保存为本地原生文件，或导出 SVG、PNG、PDF。
8. 若关闭时存在未保存的内容或主题改动，应用给出明确的保存、放弃、取消选择；单纯平移/缩放不触发 dirty 和关闭提示。

### 4.2 从脑图文件开始

1. 用户在 Finder 或 Windows 文件资源管理器中点击已关联文件。
2. 应用启动或把路径路由给已运行实例。
3. 文件通过 schema 校验后打开，节点文本、位置、尺寸、连接与主题保持一致；viewport 不进入 v1 文件，打开后使用“适合内容”。
4. 对损坏文件、不支持的未来版本或无权限路径给出可理解错误；不得修改原文件。
5. 打开期间取得 host 签发、绑定当前文档窗口的 opaque target handle 与 version token；普通保存不重复弹出 Save As 对话框，但若外部程序在本应用保存前修改了文件，必须提示冲突并停止覆盖。handle 不得由界面根据路径伪造或跨窗口复用。

### 5.2 P1：第一版完成度要求，但可在核心闭环后开发

- 服务器后端、远程 API、遥测、广告。
- 为延期能力预建抽象层。

## 6. 交互基线

具体键位需由交互任务卡产出 ADR 后执行；以下是默认提案，不是已确认产品承诺。

| 动作 | 鼠标/触控板提案 | 快捷键提案 |
| --- | --- | --- |
| 创建节点 | 空白处双击 | `N` 或双击；编辑态不得误触 |
| 编辑节点 | 双击节点或创建后直接编辑 | `Enter` 进入，`Esc` 完成/退出 |
| 移动节点 | 拖动节点 | 首版不要求键盘微移，除非可访问性验证要求 |
| 创建连接 | 从节点连接点拖向目标节点 | 首版不强制纯键盘连接 |
| 删除选择 | 选中后删除 | `Backspace` / `Delete`，macOS/Windows 统一语义 |
| 撤销/重做 | 菜单 | `Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`；Windows 可兼容 `Ctrl+Y` |
| 保存 | 菜单 | `Cmd/Ctrl+S` |
| 另存为 | 菜单 | `Cmd/Ctrl+Shift+S` |
| 打开 | 菜单 | `Cmd/Ctrl+O` |
| 全选 | 框选/菜单 | `Cmd/Ctrl+A` |
| 适合内容 | 画布控件 | 快捷键由交互 ADR 决定 |

交互约束：节点编辑态、画布快捷键态和系统菜单态必须有可预测的焦点优先级，防止输入文字时触发画布命令。

## 7. 首次使用引导

### 7.1 目标

引导不是静态产品介绍，而是把用户带过一次可操作闭环。成功标准是用户完成动作，而不是翻完页面。

### 7.2 建议流程

1. 首次启动不自动出示引导（ADR 0012：打开即全干净画布）；用户经“帮助 → 开始/重放引导”或 `⌘⇧H` 显式打开后，提供“开始 2 分钟引导”和“跳过”。中断的引导（in-progress）下次启动继续。
2. 提示用户创建第一个节点并输入内容。
3. 提示创建第二个节点、移动它并建立连接。
4. 提示撤销/重做和主题切换中的至少一项。
5. 提示保存或导出；如果保存会打断体验，可用合成的演练状态说明并让用户选择实际执行。
6. 完成后记录仅限本机的 `onboardingCompleted` 偏好；“帮助 → 开始/重放引导”（`⌘⇧H`）可重放。

### 7.3 约束

- 跳过不会禁用任何功能。
- 引导遮罩不得阻塞关闭或造成未保存数据丢失。
- 提示应锚定真实控件/画布动作，不复制另一套交互实现。
- 引导状态属于本地应用偏好，不进入脑图文档文件。

## 8. 文件与导出产品语义

### 8.1 原生文件

- 产品名、扩展名、MIME/UTI 和图标：**用户确认门槛，暂不命名**。
- 文件是 canonical UTF-8 JSON：无 BOM、固定字段顺序与数值规范、LF、末尾换行，并带整数 `schemaVersion`；详细契约见架构文档。
- 保存开始时捕获不可变文档快照；保存成功只能标记该快照，不能把保存期间的新编辑误标为 clean。
- 从文件打开或 Save As 成功后，host 返回仅限当前文档窗口使用的 opaque target handle；后续普通 Save 使用 handle + expected version token，不重复选址，窗口关闭后 handle 失效。
- 覆盖保存必须验证打开/上次保存取得的 version token；外部修改冲突不得静默覆盖。
- 保存必须采用 macOS/Windows 明确的安全提交协议；temp write、sync 或 replace 失败时保留原文件。
- 打开未来 schema 版本时拒绝覆盖并提示升级，不能静默降级。
- 第一版不承诺与其他脑图软件互导。
- v1 不持久化 viewport，pan/zoom 不进入 undo、不触发 dirty；主题持久化、进入 undo 并触发 dirty。

### 8.2 导出

- **SVG**：第一公民、语义化、无 `foreignObject`；文本使用 SVG `<text>/<tspan>`，连接使用 `<path>`，不包含选择框、连接手柄和引导层；同一 canonical 输入必须产生相同 SVG bytes/hash。
- **PNG**：从同一 SVG scene 生成 2x 位图，`2x` 定义为 scene CSS 尺寸的宽高各乘 2；默认背景策略需在导出 ADR 固定。
- **PDF**：从同一 SVG scene 生成；单页适合内容还是分页、页面尺寸与字体处理属于 Spike/ADR 门槛。
- 导出范围默认“全部内容边界 + 固定留白”；是否支持仅导出选择不进入第一版。
- 空文档导出返回明确的 `EXPORT_EMPTY_DOCUMENT`，不生成意义不明的空文件；超出 ADR 像素/页面上限时在分配大内存前拒绝并给出缩小画布或改用 SVG 的提示。
- 字体、显式换行、line-height、padding、baseline 与 node size 使用同一布局契约；UI 和 exporter 不得分别用临时 DOM 重新解释。

## 9. 非功能需求与建议基线

以下为规划建议，不是未经实机校准的保证。必须在两台代表性设备上通过 Spike 建立基线，再由用户确认 ADR。

| 指标 | 建议目标 | 测量方式 |
| --- | ---: | --- |
| 冷启动至可交互空白画布 | macOS P95 ≤ 1.5 s（Windows 验收顺延至后续专门版本） | 发布构建、本地 SSD、各 20 次，排除首次 WebView 安装 |
| 热启动/已安装 WebView | P95 ≤ 0.8 s | 各 20 次 |
| 空白文档空闲 RSS | P95 ≤ 120 MB | 窗口稳定 30 s 后采样 |
| 标准规模交互 | 300 节点 / 450 连接下拖动和缩放 P95 帧时间 ≤ 32 ms | 固定合成数据、性能采样 |
| 高风险编辑命令 | P95 ≤ 50 ms | create/move/connect/undo 自动基准 |
| 安装包/下载体积 | Tauri 方案建议每平台 ≤ 25 MB；Electron 作为对照实测 | 签名/未签名构建均记录，不把不同格式混比 |
| 原生文件保存 | 标准规模 P95 ≤ 200 ms | 本地 SSD，20 次 |
| 2x PNG 导出 | 标准规模 P95 ≤ 3 s | 固定字体、固定 scene bounds |

必须记录测试硬件、OS、CPU 架构、WebView2 状态和构建类型。“轻量”最终门槛由双平台 Spike 数据校准，不以开发机单次观感代替。

## 10. 质量与可访问性

- 所有重要操作有菜单入口或可发现控件，快捷键不是唯一入口。
- 白/黑主题的正文、节点边界、连接、选择态、焦点环满足 WCAG 2.2 AA 的可辨识目标；图形对象的非文本对比至少按 3:1 设计。
- 键盘焦点清晰，退出节点编辑后回到合理的画布对象。
- 错误信息说明“发生了什么、原文件是否安全、用户下一步能做什么”。
- 示例与测试文件只能使用合成数据。
- 固定 renderer/font 下，locale、timezone 和 DPI 变化不改变 canonical SVG hash；外部 SVG/PDF 查看器只承诺 ADR 定义的兼容容差，不声称任意查看器像素完全一致。

## 12. 发布与许可边界

- [from-user] 终端用户始终可免费使用，包括工作中使用和把导出脑图交付客户。
