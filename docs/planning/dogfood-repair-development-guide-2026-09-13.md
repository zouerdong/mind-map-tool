## 具体修法

### 1. 状态同步与错误处理

检查 `editor-canvas.tsx`、`use-canvas-session.ts`、`geometry-barrier.ts` 和 `mindmap-app.tsx`。每次成功修改 canonical 文档必须驱动对应视图更新。画布内部命令走 `api.commit`，外部命令与屏障提交须及时通知组合根；保存状态不能替代文档版本信号。

检查屏障 ready 分支异常是否留下无人处理的 rejected Promise；队列部分提交后失败时，已提交内容必须通知 UI，未提交意图保留，保存不得漏掉意图。核查 `cancelPendingNode` 是否误删文档字体意图。测试在真实有尺寸差异的字体和真实 React Flow 下验证，不能只读 session 判断成功。

投影检查应比较同一文档快照与对应投影。可以把纯函数断言留在契约测试，但必须补显示同步回归，禁止用删除检查掩盖陈旧画面。原生菜单的主题、整理、撤销/重做、保存和导出分别实际点击一次；记录独立问题，勿先归因为同一个 bug。

### 2. 已确认视觉的完整接线

以 `visual-state-tokens-2026-09-06.md` 和 `input/样式参考.JPG` 为基线：暖白画布、近黑卡片、橙色强调、120px 最小卡宽、16px 正文、完整内距。字体、眉题、正文和 runs 的测量共用 `measureNodeVisual`。

逐条检查创建、普通文字编辑、字号/粗体、眉题、字体切换、屏障队列和编辑中尺寸预览。尤其普通正文编辑必须保留眉题高度；不携带 runs 时要与 core 清除 runs 的实际语义一致，不能用旧 runs 测量后写入新纯文本。编辑 textarea 的内距、文字位置也要与提交后一致。

不批量修改已有文件。打开既有文档不静默重排；用户编辑引起的尺寸变更可撤销。隐藏框线须实际隐藏填充并使用正确文字颜色；确认纵向布局端口、整理后连线与再次编辑一致。发现超出本卡的布局算法问题，准确回报，不无关重构。

### 3. 最小界面方案

- 无节点时：暖白或黑板干净画布，底部居中低对比但可读提示“ 双击创建 · ⌥Space ”，不遮挡输入。
- 至少两个节点时：右上角一个浮动“整理 ⇧⌘L”按钮；零/一个节点时不显示。按钮和系统菜单调用同一 dispatcher。
- 保留系统菜单中的文件、导出、主题和布局方向；不恢复整条常驻顶栏。
- 上下文工具条仅在选中时出现，定位到主选节点附近；贴边时限制在视口内，小窗口不溢出，输入时不抢焦点。
- 无自动大面积引导、模板墙或新增运行时依赖。按现有主题 token 实施，无需新设计风格。

### 4. 轻量验收方式

自动验证覆盖受影响的 UI/应用集成门及静态检查。原生验证聚焦一条真实用户路径：创建三个含中文节点 → 编辑 → 连接 → 样式/字体 → 整理 → 撤销重做 → 保存重开 → 四格式导出。附暖白、黑板、选中和整理后截图。

对照参考确认卡片和文字实际外观；不要用预制尺寸夹具代替“从空白创建”的验证。无需重新执行 advisory、20轮性能、VoiceOver 或完整发布矩阵。修复后的原生实测完成后再提交独立审阅；负责人决定是否恢复试用。
