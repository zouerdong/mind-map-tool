## 3. 产品意图

为创意工作者提供一个几乎没有进入成本的思考空间：用户在想法出现时打开应用，立即面对一张空白画布，通过文字节点和连接关系外化思路，而不是先理解复杂工具或付费体系。

项目成立的理由是市场上缺少同时满足以下条件的产品，而不是为了必须拥有一款自研软件：

- 终端用户永久免费、无广告。
- 本地运行、无需账号、无需联网。
- macOS 与 Windows 可用。
- 界面和功能极简。
- 安装、启动和运行负担低。

## 4. 目标形态

### 4.1 核心隐喻

应用是一张自由白板或黑板，而不是自动生成树形结构的传统脑图。用户可以：

- 在画布任意位置创建文字节点框。
- 编辑节点内容。
- 自由移动节点。
- 主动在任意相关节点之间创建连接。
- 通过鼠标和快捷键完成核心操作。
- 在白板与黑板外观之间切换。

### 4.2 启动与文档

- 点击应用图标：始终创建新的空白文档。
- 点击已保存的脑图文件：打开该文件对应的脑图。
- 用户主动选择保存到本地原生脑图文件。
- 关闭时选择不保存：该未保存会话不在下次启动时恢复。
- 不引入账号、云端文档或默认跨设备同步。

### 4.3 首次使用引导

第一版包含交互式首次使用引导，不包含幻灯片式“演示模式”。引导应：

- 出现在首次进入空白画布的适当时机。
- 通过动态提示解释鼠标动作与快捷键。
- 让用户实际完成一次完整建图流程，而不是阅读静态功能列表。
- 覆盖创建、编辑、移动、连接、保存或导出等核心动作。
- 具体快捷键、文案、动画、是否可跳过与再次打开，由交互规划给出方案和验收标准。

### 4.4 导出

第一版支持：

- PNG
- PDF
- SVG

导出范围、背景处理、字体嵌入、矢量保真和超大画布分页策略由技术规划明确，不得在实现阶段临时决定。

## 5. 第一版范围

### 5.1 In Scope

- macOS 与 Windows 桌面应用。
- 自由平移、缩放的空间画布。
- 文字节点的创建、编辑、移动和删除。
- 节点之间连接的创建与删除。
- 基本选择、撤销与重做行为。
- 鼠标操作和核心快捷键。
- 白板/黑板两种画布外观。
- 本地原生脑图文件的保存、打开和系统文件关联。
- 首次使用交互式引导。
- PNG、PDF、SVG 导出。
- 可公开放置于 GitHub 的源码与免费安装包交付方案。
- 自动化测试、跨平台手工验收说明和发布前检查。

### 5.2 Out of Scope / Non-goals

第一版明确不做：

- 账号系统。
- 云同步或云端存储。
- 多人实时协作。
- 移动端应用。
- Web 版。
- AI 自动生成脑图。
- 模板库和装饰样式库。
- 图片、附件、音视频或其他富媒体节点。
- 传统树状脑图的自动布局。
- 幻灯片、逐页聚焦或全屏讲解型演示系统。
- 插件系统、在线市场或第三方扩展平台。
- 服务端后台；在当前范围内没有正当的后端需求。

延期项可以在第一版完成后逐个评估，但不得提前为其建立空泛架构或增加首版复杂度。

## 6. 许可与分发约束

### 6.1 已确认原则

- 所有终端用户均可免费使用，包括工作场景和向客户交付脑图。
- 免费的非商业传播被允许。
- 第三方不得未经授权通过软件本身收费、转售或包装成商业产品。
- 对软件本身的商业化需要单独付费授权。
- 公开发布前必须为仓库与二进制分发选择一致的许可文本。

### 6.2 术语与待办

该模式不是 OSI 定义的开源，更准确的描述是“源码可见”或“双重许可”。许可证选择属于规划阶段的独立决策项，需要：

- 比较标准源码可见许可证与定制双重许可。
- 明确“软件本身商业化”的可执行定义。
- 检查第三方依赖许可证兼容性。
- 在公开发布前进行法律层面的复核。

## 7. 决策边界

### 7.1 当前 Agent 可以执行

- 输出产品、架构、工程、质量和交付规划。
- 形成开发指导文件和可独立分派的任务卡。
- 为每张任务卡定义依赖、输入、输出、验收标准和验证命令。
- 在其他 Agent 实现完成后进行代码审阅、功能验收和规格一致性检查。

### 7.2 当前阶段禁止

- 不实现前端、桌面端或任何产品代码。
- 不创建本范围不需要的服务端后端。
- 不代替用户派发实现 Agent。
- 不公开发布仓库、安装包或许可证。
- 不在未经确认时扩大第一版功能范围。

### 7.3 必须由用户确认

- 最终桌面技术栈与其 ADR。
- 原生脑图文件格式及兼容承诺。
- 最终许可证和商业授权文本。
- 第一版范围增删。
- GitHub 公开发布、安装包分发和任何对外上线操作。

## 8. 可测试验收标准

以下标准是后续规划与任务卡的最低验收基线：

1. 在 macOS 和 Windows 上点击应用图标，均进入新的空白画布，而不是恢复上次未保存会话。
2. 用户可在任意画布位置创建、编辑、移动和删除文字节点。
3. 用户可在任意两个节点间创建和删除连接；移动节点后连接保持正确附着。
4. 用户可通过鼠标完成完整建图流程，并可通过已定义的核心快捷键完成高频动作。
5. 用户可在白板与黑板外观之间切换，节点、连接和选择状态在两种外观下均清晰可辨。
6. 用户可把文档保存为本地原生脑图文件，再次打开后节点内容、位置、连接和必要文档状态保持一致。
7. 点击已关联的脑图文件可直接启动应用并打开对应文档。
8. 用户明确选择不保存并关闭后，下次点击应用图标得到空白画布；关闭安全交互不得造成无提示的意外数据丢失。
9. 首次使用引导可以带领新用户实际完成一次节点创建、编辑、移动、连接和保存或导出流程。
10. 用户可以跳过首次引导，完成后不会在每次启动时强制重复；应提供再次访问方式。
11. 同一脑图可以导出 PNG、PDF 和 SVG；导出结果不得缺失节点、连接或文字。
12. 应用不要求账号或联网，不包含广告、云同步、遥测或服务端依赖。
13. 规划阶段必须给“轻量”定义可重复测量的启动时间、空闲内存、安装包体积和交互响应目标，并为 macOS/Windows 指定测试环境。
14. 第一版的自动化测试和人工验收清单覆盖本节所有行为；无法自动化的平台行为必须有可重复的人工步骤。

## 9. 假设、修正与剩余规划决策

### 9.1 已解决

- “收费是唯一根因”被修正：真正目标是免费、本地、极简、轻量条件的组合。
- “本地开发即可完成产品”被修正：公开双平台分发还需要打包、兼容、许可与验证工作。
- “商业脑图产出需要收费”被修正：收费边界只保护软件本身的商业化，不限制用户产出。
- “演示模式”被修正为首次使用交互式引导。
- “思维导图等于树状布局”被否定：第一版是自由空间节点图。

### 9.2 由规划阶段决定并记录

- 桌面运行时、前端技术栈和渲染方案。
- 画布/图形库是采用第三方依赖还是自研最小层。
- 原生文件扩展名、版本字段、schema、向前兼容和损坏恢复策略。
- 节点与连接的精确交互、快捷键和撤销/重做命令模型。
- 关闭未保存文档的安全确认流程。
- 导出语义和大画布策略。
- 首次引导的触发、跳过、重放、文案和动画。
- “轻量”的量化预算。
- 源码可见/双重许可的具体法律方案。

每项不可轻易逆转的技术决定必须写入 `docs/decisions/`，并遵守根级 `AGENTS.md`。

## 10. 规划交付合同

后续规划必须至少输出：

- 产品开发指导文件。
- 系统架构与依赖方向。
- 技术选型对比和 ADR 草案。
- 数据模型与原生文件格式草案。
- 交互命令表与快捷键建议。
- 测试策略、性能预算和双平台验收矩阵。
- 发布与许可工作流，但不得执行公开发布。
- 可独立分派给其他 Agent 的任务卡。

每张任务卡必须包含：唯一 ID、目标、上下文、依赖、允许修改范围、明确非目标、实施步骤、交付物、验收标准、验证命令、风险和回报模板。任务卡应按依赖关系排序，尽量减少多个 Agent 同时修改同一文件。

## 11. 技术上下文

- 仓库为绿地项目，目前只有框架无关工程骨架，无产品代码或依赖。
- 现有职责边界：`apps/desktop/`、`packages/core/`、`packages/ui/`、`packages/platform/`、`tests/`。
- 服务器端后端与当前需求不匹配，不应因为用户口语中的“前后端开发”而被默认创建。
- 规划应优先评估能显著降低包体和空闲资源占用、同时支持可靠双平台打包的桌面技术栈。

## 12. 压力测试记录

- Contrarian：用“若已有免费成熟工具”验证自研并非目的本身。
- Simplifier：把首个里程碑收敛为个人双平台可用，再规划公共分发。
- Ontologist：把许可保护对象从模糊的商业产出还原为软件本身的商业化。
- Pressure pass：Round 2 复查 Round 1 的动机，产品定位从“自研”转为“填补低摩擦组合空缺”。
