# 前端设计介入策略与 UXD-001 任务卡

## 1. 结论

**不要等全部功能开发完成后再设计前端。现在就应启动“设计定义”，但暂时不要直接重写生产 UI。**

当前界面是工程验证壳：顶部长排按钮、浏览器 dev 状态、多个临时 panel 和 inline style 主要用于证明功能与测试锚点，不代表最终产品形态。继续让功能 Agent 自行叠加临时 UI，最后再统一设计，会形成大量交互返工；现在直接做精细视觉实现，又会被 MRT-004 多窗口和 MRT-008/009 操作面改动反复推翻。

正确节奏：

```text
现在：UXD-001 体验定义/视觉方向/原型（不改生产代码）
  与 MRT-003V、MRT-004 工程工作并行
MRT-004 通过 + UXD-001 获用户确认：UXI-001 实现 App Shell 与核心画布界面
MRT-008/009 核心交互完成：UXI-002 做状态补齐、动效、a11y 与最终视觉验收
```

## 2. UXD-001 定位

**类型：产品体验与视觉设计任务**  
**状态：READY，可立即启动**  
**产出：设计规格、原型与用户决策，不修改生产 UI**  
**建议能力：Product Design 工作流；需要时进行一次聚焦于界面的深度访谈**

## 3. 已知产品原则

- 打开应用就是一张空白纸，不经过首页、模板库、账号或云入口。
- 画布是绝对主角，常驻 chrome 应尽可能少。
- 用户在任意位置快速放节点、写想法、自由连线。
- 支持白板与黑板；主题是文档状态。
- 重点是“快速表达逻辑与关联”，不是复杂排版软件。
- 保存为本地脑图文件；不保存关闭后下次仍是新白纸。
- 首次操作演示要自然走完完整创建流程。
- SVG/PNG/PDF 导出是 v1 必备。
- 关闭、错误、冲突等安全状态必须明确，但不能让工程提示主导日常界面。

术语需收口：此前用户所说“演示模式”实际描述的是首次使用教学。设计中优先称“新手引导”或“操作演示”，避免与全屏展示脑图的 presentation mode 混淆；若仍需要真正的演示/放映模式，必须另行确认范围。

## 4. 必须先回答的设计问题

1. 常驻工具条是否存在；若存在，最多保留哪些动作？
2. 新建节点的主入口是双击、快捷键、浮动按钮还是组合？
3. 连线进入方式如何在“可发现”与“不打扰”之间平衡？
4. 选中节点后出现何种最小 contextual controls？
5. 白板/黑板切换放在哪里，是否应常驻？
6. 保存与导出是菜单、命令面板还是短暂浮层？
7. 首次引导如何不把空白纸变成教程页面？
8. 空白、编辑、选择、连线、拖动、多选、保存中、冲突、关闭确认分别是什么视觉状态？
9. 窗口标题、dirty 指示和本地文件名如何低干扰呈现？
10. 用户是否需要真正的全屏“放映脑图”，还是只需要首次教学？

## 5. 任务步骤

### UXD-001A：现状审计

- 在最新 macOS bundle 上截取关键状态，不以浏览器 dev 代替原生窗口。
- 标出哪些是工程临时壳、哪些是必须保留的产品能力。
- 审计层级、密度、焦点、可发现性、主题一致性和错误状态。
- 只报告，不改代码。

### UXD-001B：聚焦访谈与体验原则

- 围绕“打开后前 30 秒”“连续记录 10 个想法”“连接/整理”“保存/关闭”“再次打开文件”访谈。
- 确认用户最反感的常驻 UI、期望的工具隐身程度、快捷键依赖程度。
- 输出 5～7 条可判断设计好坏的原则，而不是形容词堆砌。

### UXD-001C：2～3 个视觉/交互方向

每个方向必须使用同一组真实状态，不能只画一张空白首页：

- 空白白板。
- 空白黑板。
- 有 8～12 个节点与连接的工作态。
- 节点选中和编辑态。
- 连线态。
- 导出入口。
- 新手引导一步。
- 保存失败/冲突。
- 关闭三分支。

建议探索但不预设结论：

- **隐形画布型**：无常驻顶栏，边缘/右键/命令面板唤起工具。
- **极薄控制条型**：仅文件、主题、导出三个常驻入口，其余 contextual。
- **桌面纸张型**：窗口 chrome 极弱，节点和线具有轻微纸笔质感，黑板为同构反色。

### UXD-001D：用户选择 Gate

- 并排展示三个方向的同状态对比。
- 清楚列出可发现性、学习成本、键盘效率、实现复杂度和跨平台一致性。
- 由用户选择一个方向或明确组合规则；Agent 不得自行宣布定稿。

### UXD-001E：可实现规格

方向获批后输出：

- 页面/浮层信息架构。
- 组件与状态矩阵。
- 白/黑主题 tokens。
- 字体、字号、间距、圆角、阴影、线条和动效规格。
- keyboard/focus/IME/a11y 行为。
- 响应式窗口最小尺寸策略。
- onboarding 完整路径。
- UXI-001/002 的文件级实施映射和不应改动的领域逻辑边界。

## 6. 文档落点

新增正式目录前先更新 `docs/product/README.md`，定义内容放置、命名、维护责任和过期规则。建议产出：

```text

docs/product/ui-state-matrix.md
docs/product/ui-design-direction.md
docs/planning/ui-implementation-map.md
```

参考图/原型若进入版本控制，必须记录来源和许可证；临时探索放 `.tmp/uxd-001/`，不冒充最终规格。

## 7. 禁止事项

- 不在方向获批前重写 `MindMapApp`、工具条或 Canvas CSS。
- 不把当前工程壳当作必须保留的布局。
- 不用漂亮空白截图代替复杂工作态和错误态。
- 不引入新的 UI framework/runtime dependency。
- 不改变 core command、文件格式、保存、close、launch 语义。
- 不把“极简”理解为隐藏所有入口；首次用户仍需可发现。
- 不等所有工程卡完成后才第一次向用户展示方向。

## 8. 完成定义

- 用户看到了至少两个可比较的完整方向。
- 每个方向覆盖白板/黑板、工作态、编辑/连线、保存错误和关闭确认。
- 用户明确选择方向并确认体验原则。
- 正式 brief/state matrix/方向文档可直接约束工程 Agent。
- UI 实施被拆成 UXI-001（结构）与 UXI-002（收尾），并标明与 MRT-004/008/009 的依赖。
- 没有修改生产 UI 或新增依赖。

## 9. 建议实施时点

- **立即**：UXD-001A～D。
- **MRT-004 通过后**：UXD-001E 定稿并启动 UXI-001，替换工程壳的 App Shell、文件入口、主题入口、导出入口与 modal 视觉。
- **MRT-008/009 通过后**：UXI-002 完成节点/连线/多选/键盘状态、微动效、响应式与最终 a11y/视觉回归。

这样既不会把不符合预期的界面拖到最后，也不会在窗口与交互架构仍变化时反复重做高保真前端。
