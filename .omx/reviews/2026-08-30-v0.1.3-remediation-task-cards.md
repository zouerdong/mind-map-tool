# Mind Map Tool v0.1.3 审查整改任务卡

## 使用规则

这些卡用于后续 Agent 派发。**按编号串行执行，除非卡片明确允许并行。** 每个 Agent 开始前必须读取根 `AGENTS.md`、本任务卡和 `2026-08-30-v0.1.3-code-review.md`。

通用交付要求：

1. 先补能稳定暴露问题的失败测试，再修改实现；不得修改测试来迁就错误行为。
2. 只改卡片“允许范围”；发现跨卡问题时记录并停止扩张，不顺手重构。
3. 产品范围或关键架构改变必须先更新 PRD/ADR；不得用实现偷偷取消多窗口、字体嵌入或其他 P0。
4. 不覆盖旧质量证据；新证据必须带 commit、clean/dirty、平台、架构、执行命令、退出码和 hash。
5. 每张卡回报：根因、修改文件、测试清单、命令原始结果、剩余风险、`git diff --check`、`git status --short`。
6. 卡片验收失败即停止，不进入下一张。

## 执行波次

| 波次 | 任务卡 | 目的 | 是否可并行 |
| --- | --- | --- | --- |
| A | MRT-001 → MRT-002 → MRT-003 | 保存、dirty、关闭数据安全 | 否 |
| B | MRT-004 → MRT-005 | 窗口生命周期与不可信文件边界 | 否 |

| E | MRT-010 → MRT-011 → MRT-012 | 重建门禁、真实性能、发布硬化 | 否 |

## MRT-001：重建保存队列状态机

**优先级**：P0，第一张执行卡  
**对应问题**：CR-001  
**依赖**：无

**目标**

消除 `null` 多义性和永不出队问题，使 ordinary/save-as 保存请求严格串行、每个 intent 恰好消费一次，并以开始执行时的最新文档重新捕获快照。

**允许范围**

- `packages/core/src/document-session.ts`
- 对应 core 测试
- `apps/desktop/src/app/file-commands.ts`
- 新增/调整文件流集成测试
- 如公共类型必须变化，可最小修改 `packages/core/src/index.ts`

**实施要点**

- 定义可判别请求结果，例如 `no-target | queued | snapshot`，禁止继续用同一个 `null` 表达不同状态。
- 队列只有一个 owner；提供显式 `takeNextSaveIntent()` 或等价原子操作，取出时即出队。
- ordinary 与 save-as intent 都保留自己的语义；不得把排队 Save As 悄悄降级成 ordinary。
- 明确失败后的队列策略，并让调用方得到终态；禁止 fire-and-forget 无限循环。

**必测场景**

- 已有 target 时快速按两次保存：不弹 Save As，commit 恰好 2 次，队列最终为 0。
- 第一次保存进行中继续编辑再保存：第二次 bytes 是最新状态；第一次完成不能错误清 dirty。
- 首次 Save As 进行中再次保存/Save As；取消授权；commit 冲突；失败后用户重试。
- 队列无论成功/失败都不会自旋，不会留下不可达 intent。

**验收命令**

```bash
pnpm --filter @mindmap/core test
pnpm test:unit
pnpm typecheck
pnpm lint
git diff --check
```

**完成定义**

所有必测场景有断言提交次数、对话框次数、最终 handle/token、saved identity、dirty、队列长度；不得只断言函数返回值。

## MRT-002：恢复历史 identity 与 dirty 契约

**优先级**：P0  
**对应问题**：CR-002  
**依赖**：MRT-001

**目标**

让 undo/redo 返回原历史状态节点，只有新分叉编辑分配新 identity，使 dirty 与保存点语义符合 Accepted ADR 0003。

**允许范围**

- `packages/core/src/history.ts`
- `packages/core/src/history.test.ts`
- `packages/core/src/document-session.test.ts`
- 必要的 core 测试夹具

**必测场景**

- 保存 S2 → undo 到 S1 为 dirty → redo 到原 S2 为 clean。
- 连续 undo/redo 往返，canonical state 与 identity 都稳定。
- undo 后提交新命令会截断 redo，分叉 identity 新发且不复用。
- 保存进行中发生 undo/redo 时，完成回执只标记冻结快照的 identity。

**验收命令**

```bash
pnpm --filter @mindmap/core test
pnpm test:unit
pnpm typecheck
pnpm lint
git diff --check
```

**停止条件**

如果发现 ADR 0003 无法实现，先提交新的 ADR 提案给项目负责人，不能自行改成 revision/index dirty 判定。

## MRT-003：实现 Tauri 原生 dirty-close 三分支

**优先级**：P0  
**对应问题**：CR-003  
**依赖**：MRT-001、MRT-002

**目标**

任何原生窗口关闭/退出都先经过 Save、Discard、Cancel；失败和冲突不关闭窗口。

**允许范围**

- `apps/desktop/src-tauri/src/lib.rs` 与最小 IPC/窗口模块
- `apps/desktop/src/app/mindmap-app.tsx`
- `apps/desktop/src/app/file-commands.ts`
- 生命周期 ports/types 及直接测试
- `tests/e2e/macos/` 中本卡真实用例

**实施要点**

- host 捕获 `CloseRequested` 并 `prevent_close`，用 request/response correlation 防止重复关闭竞态。
- Save 等待 MRT-001 的真实保存终态；失败/冲突保留窗口和 capability。
- Discard 明确撤销该窗口 ledger/capability 后再关闭；Cancel 零副作用。
- 应用级退出需对多窗口逐个处理，不得只保护当前 WebView。

**必测场景**

- clean 窗直接关闭。
- dirty 未命名文档：Save→Save As 成功后关闭；取消 Save As 后不关闭。
- dirty 已命名文档：保存成功关闭；冲突/只读/IO 失败保持窗口。
- Discard 关闭且不写盘；Cancel 不关闭；重复点击关闭只出现一个流程。

**验收命令**

```bash
pnpm test:unit
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
pnpm typecheck
pnpm lint
git diff --check
```

并执行真实 macOS 三分支用例，证据不能由 jsdom/unit 替代。

## MRT-004：实现真实多窗口与可靠启动 intent 协议

**优先级**：P0  
**对应问题**：CR-004、CR-005  
**依赖**：MRT-003

**目标**

满足 AC-01/AC-07：每窗口独立 session；不同文件新窗；同文件聚焦；Dock activation 新空白窗；dirty 窗不被替换；启动 intent 不丢、不乱序、不提前 ack。

**允许范围**

- `packages/platform/src/lifecycle/`
- `apps/desktop/src-tauri/` 的窗口/启动/IPC 代码
- `apps/desktop/src/app/` 的窗口装配与启动动作
- 对应 platform/unit/integration/macOS E2E
- 如架构说明变化，同步 `docs/architecture/`；关键取舍先写 ADR

**实施要点**

- 建立真实 window registry，host 与 UI 使用同一 window identity；每个窗口绑定独立 DocumentSession 和 capability ledger。
- adapter 先订阅事件，再完成 ready snapshot；对启动队列串行消费。
- action 返回 awaitable 终态；成功或用户明确拒绝才 ack，瞬时失败保留 intent。
- 同文件 identity 使用 canonical path/host identity，不依赖 UI displayPath 字符串比较。

**必测场景**

- 冷启动连续传入 A、B 两文件，最终两个窗口分别为 A、B，不受读取完成顺序影响。
- 已运行时打开 B；重复打开 A 只聚焦 A；A dirty 时打开 B 不替换 A。
- listener 安装与 snapshot 之间注入事件，intent 不丢。
- 用户取消 dirty 决策、文件读取失败、窗口创建失败时 ack 行为正确。
- Dock/图标 warm activation 新建空白窗口。

**验收命令**

```bash
pnpm --filter @mindmap/platform test
pnpm test:unit
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
pnpm typecheck
pnpm lint
pnpm build
git diff --check
```

最终必须有真实 Finder/Dock/macOS 多文件证据。

## MRT-010：重建唯一质量门禁与可信证据链

**优先级**：P1，发布阻断  
**对应问题**：CR-016、CR-019  
**依赖**：MRT-001～MRT-009

**允许范围**

- `scripts/quality/`
- `tests/e2e/`
- `package.json` 的本地质量脚本
- `docs/quality/` 的状态、索引、证据 schema 和当前执行结果
- 不修改 CI/CD；若需要 CI 改动，按 AGENTS 红线先询问

- authoritative gate 至少含 format、typecheck、lint、unit、真实 integration、a11y、build、cargo test、clippy、boundaries、JS/Cargo license、network、export golden、性能。

- 脚本声明的 E2E case 必须与实际 case registry 一致；不得复制同一 suite JSON 作为不同真实场景证据。
- 人工矩阵未执行就保持未验证，不得由自动化自动勾选。


**完成定义**

对“缺 artifact、旧 commit、dirty、宣称不存在 case、人工矩阵空白”均有负向测试并返回非零；旧证据保留历史身份，不覆盖伪装为新执行。

## MRT-012：发布前文件安全、许可证、CSP 与治理收口

**优先级**：P2，最后收口  
**对应问题**：CR-018、CR-020、CR-021  
**依赖**：MRT-010、MRT-011

**目标**

让文件 durability 承诺与实际一致，补 Cargo 许可证核查和最小 CSP，并同步阶段/Gate/版本文档。

**允许范围**

- `apps/desktop/src-tauri/src/file/` 与故障注入测试
- Tauri 安全配置（修改前先按 AGENTS 红线确认是否属于发布/生产配置）
- `scripts/quality/` 的 Cargo license audit
- `docs/decisions/`、`docs/quality/`、根 `AGENTS.md`/README 的事实同步
- 版本号变更不得顺带发布

**实施要点**

- 明确 token 检查到 replace 之间的 TOCTOU 余量；能加强则加入文件 identity/原子条件，不能则降低产品承诺并保留冲突提示。
- directory fsync 失败要么结构化上报，要么证据明确写 best effort；增加各 sync 阶段故障注入。
