# Mind Map Tool v0.1.3 全面代码审查

## 1. 结论

**当前发布状态：BLOCKED。**

审查基线为 `main@d57d9b9`（标签 `v0.1.3`）。现有 `pnpm quality` 虽然通过，但不能代表产品已达到 v1 验收条件：本次确认了 **4 个 P0、13 个 P1、4 个 P2**。其中保存队列、redo 状态身份、原生脏文档关闭、启动/多窗口路由可能直接造成错误保存、错误 dirty 状态、覆盖当前文档或丢失未保存内容。

在 P0 全部关闭、对应回归测试进入唯一总门禁、macOS 人工矩阵完成之前，不应进入 G2、安装包签发或对外发布。

本次只审查并新增审查文档，未修改产品源码、配置、测试或既有质量证据。

## 3. 阻断级问题（P0）

### CR-001 保存队列不会出队，连续保存可进入无限提交；第二次普通保存还可能错误弹出 Save As

**证据**

- `packages/core/src/document-session.ts:133-149`：保存进行中时只向 `queue` 追加并返回 `null`。
- `packages/core/src/document-session.ts:170-189`：成功/失败调用的 `drainQueue()` 是空操作，没有移除任何 intent。
- `apps/desktop/src/app/file-commands.ts:103-109`：把所有 `null` 都解释为“没有目标”，转入 Save As；无法区分“正在排队”。
- `apps/desktop/src/app/file-commands.ts:165-184`：只检查 `queuedSaveCount > 0`，重新请求普通保存，却从未消费队首；一次排队后可不断提交。
- `packages/core/src/document-session.test.ts:129-145` 只断言队列曾为 1，没有验证出队、提交次数或最终停止。

**影响**

重复写盘、文件冲突、错误对话框、后台循环；失败路径还可能保留一个永远无法消费的队列。该问题违反 ADR 0003 的“并发保存串行化，后续请求排队并重新捕获快照”。

**要求**

用可判别结果表达 `no-target / queued / snapshot`，由单一队列驱动显式消费 intent；每个保存请求有明确完成结果。必须增加“两次快速保存”“保存期间继续编辑”“失败后重试”“Save As 排队”的跨层回归。

### CR-002 redo 重新分配 identity，违反 Accepted ADR，并导致回到已保存状态后仍显示 dirty

**证据**

- `docs/decisions/0003-core-schema-session-save.md:30-33`：undo/redo 必须返回原历史节点及原 identity；只有分叉编辑分配新 identity。
- `packages/core/src/history.ts:52-64`：redo 重放命令并覆盖历史项，产生新 identity。
- `packages/core/src/history.test.ts:81-94`：测试反而把“新 identity”写成期望，与 ADR 相反。

**影响**

保存状态 S2 → undo 到 S1 → redo 回相同 S2 后，session 仍判定 dirty；关闭提示、标题、保存行为都会错误。

**要求**

redo 只移动 cursor 并返回已存的历史节点；分叉 commit 才创建新 identity。测试必须覆盖“save→undo dirty→redo clean”、多次往返 identity 稳定、分叉后 redo 被截断且新 identity 不复用。

### CR-003 原生窗口关闭没有三分支保护，脏文档可能直接丢失

**证据**

- `apps/desktop/src/app/mindmap-app.tsx:233-240` 只有浏览器 `beforeunload`，注释已承认 native 缺口。
- `apps/desktop/src-tauri/src/lib.rs:78-94` 只处理 `Destroyed` 与 `Focused`，没有拦截 `CloseRequested`。
- `apps/desktop/src/app/mindmap-app.tsx:422-449` 的通用确认只有 discard/cancel，没有 save。
- `docs/product/v1-product-spec.md:56` 与 `docs/quality/v1-test-spec.md:66` 明确要求 save/discard/cancel。
- `docs/quality/mm-090-manual-matrix.md:21` 仍未执行。

**影响**

用户点击窗口关闭或退出应用时，浏览器语义不能保证 Tauri 原生窗口被阻止；未保存内容可能消失。

**要求**

建立 host 与 UI 的异步 close handshake：先 `prevent_close`；Save 必须等待提交成功后关闭，冲突/失败保持窗口；Discard 撤销窗口 capability 后关闭；Cancel 不改变状态。必须真实 macOS E2E/人工验证三分支。

### CR-004 当前“单窗口实现”违反 P0 多窗口/启动契约；连续打开文件存在覆盖和竞态

**证据**

- `apps/desktop/src/app/mindmap-app.tsx:248-270`：`open-in-window` 与 `open-new-window` 都加载到同一个 session；窗口清单永远只有 `main`。
- 同段异步 action 以 fire-and-forget 执行；连续 intent 可并发 `openPathFlow`，最后完成者覆盖当前文档。
- `packages/platform/src/lifecycle/launch-router.ts:31-46` 的契约假设真实多窗口并承诺不覆盖 dirty 窗口。
- `apps/desktop/src-tauri/src/lib.rs:110-122` 只在 reopen 且无可见窗口时摄入 activation；已存在窗口时点击 Dock 不会创建规格要求的新空白窗口。
- `docs/product/v1-product-spec.md:204,210` 要求 Dock/图标激活新空白窗、同文件聚焦、不同文件新窗、dirty 窗不被替换。

**影响**

Finder 连续打开多个文件、同文件重复打开、Dock 激活、dirty 窗存在时的行为均不满足 v1；并发读取还可能让用户看到错误文件或覆盖当前 session。

**要求**

实现每窗口独立 DocumentSession、真实窗口注册表和 create/focus 命令；intent 串行处理并在动作完成后 ack。若产品决定取消多窗口，必须先由项目负责人修改 PRD/ADR，不能用当前实现静默改变 P0。

## 4. 高优先问题（P1）

### CR-005 生命周期适配器可能丢事件，且在动作完成前提前 ack

- `packages/platform/src/lifecycle/tauri-adapter.ts:39-45` 先取 ready snapshot、后安装 listener，中间到达的 host 事件可能没有消费者且不会再次 flush。
- `packages/platform/src/lifecycle/launch-router.ts:113-118` 的 action callback 是同步 `void`，随后立即 ack；用户取消、打开失败、异步动作尚未完成时 intent 已被删除。
- 修复方向：先订阅后快照；action 返回可等待的终态结果；仅成功完成或用户明确拒绝时 ack，瞬时失败保留重试语义。

### CR-006 命令层可生成 schema 自己无法重新读取的文档

- `packages/core/src/commands.ts:104-157` 的创建、编辑、移动没有完整执行 schema 上限、有限数、尺寸、runs 等不变量。
- `packages/ui/src/canvas/node-text-editor.tsx:70-76` 没有文字上限；`packages/core/src/schema.ts:149-150` 打开时却拒绝超过 10,000 字符。
- 结果是“应用允许编辑并保存，但下次无法打开”。校验必须收口在 core，不应只靠 UI。
- 修复方向：共享字段验证器；任何成功命令序列都必须通过 `validateDocument` 和 canonical round-trip；UI 同时给出友好限制。

### CR-007 恶意/损坏 JSON 可让 decode 抛异常；host 又会在限额判断前整文件读入内存

- `packages/core/src/schema.ts:145-150,178-181,216-221` 在确认嵌套值为非 null object 前直接解引用；`nodes:[null]`、`edges:[null]`、`runs:[null]` 会抛 TypeError，而不是返回结构化错误。
- `apps/desktop/src/app/file-commands.ts:78-99` 没有捕获 decode 内部异常。
- `apps/desktop/src-tauri/src/file/mod.rs:77-85` 先 `std::fs::read`，50 MB 限制发生在分配和 IPC 传输之后。
- 修复方向：所有嵌套输入逐级 guard；对任意限额内 bytes，decode 不得 throw；host 先读取 metadata 并 bounded read，返回稳定错误码。

### CR-008 SVG 多行文字会重叠在第一条 baseline

- `packages/export/src/scene.ts:163-203` 为每个 segment 计算独立 `baselineY`。
- `packages/export/src/svg.ts:42-58` 只给父 `<text>` 写首行 `y`，每个 `<tspan>` 没有自己的 `y`。
- 现有 golden 由同一 SVG 实现派生 PNG/hash，可能“自洽地错误”，不能独立证明视觉正确。
- 修复方向：每行/segment 输出正确 baseline；加入独立参考几何或真实 raster 对比，核对 SVG/PNG/PDF 三格式。

### CR-009 SVG 字体未内嵌，文楷粗体意图也在布局阶段丢失

- `packages/export/src/svg.ts:17-69` 只有 `font-family`，没有 `@font-face`、data URI 或子集嵌入，违反 `docs/product/v1-product-spec.md:86,167-172` 的可移植导出要求。
- `packages/export/src/layout.ts:101-112` 把 `bold` 写成“是否有真粗体”的结果；到 `packages/export/src/scene.ts:174-183` 时已经无法知道文楷请求过粗体，`fauxBold` 不会生效。
- 修复方向：分离 `requestedBold` 与解析后的 font face；按 ADR 0005 实现独立 SVG 字体嵌入/子集策略；在无本机字体环境验证。

### CR-010 v1 P0 样式能力只存在于模型/渲染层，用户无法完整操作；隐藏框线也未真正隐藏

- `docs/product/v1-product-spec.md:80-86` 把节点形状、字体、局部富文本、框线列为 P0。
- `apps/desktop/src/app/mindmap-app.tsx:300-320` 工具条没有字体、形状、富文本、框线入口。
- `packages/ui/src/canvas/node-text-editor.tsx` 只能编辑整段 plain text；编辑提交会清空 runs。
- `packages/ui/src/canvas/mind-node.tsx:62-76` 在 `framesVisible=false` 时仍保留 border，只关闭阴影。
- 这是产品完成度缺口。若要延期，必须先修改 PRD；否则应补全 selection-aware UI、命令与回归。

### CR-011 键盘契约、焦点恢复和功能可发现性未达到 AC-17

- `packages/ui/src/keyboard.ts:7-47` 没有主题快捷键；多选、undo/redo/delete 等也缺少完整可发现的按钮或 native menu 闭环。
- `packages/ui/src/canvas/editor-canvas.tsx:385-405` 点击画布容器不会可靠把焦点交给 pane；既有 `docs/quality/mm-090-report.md:81` 已记录该缺陷。
- 修复方向：先建立 AC-17 键盘矩阵，再补 focus-on-pane、菜单/按钮、IME 与 WebKit 真机测试，避免只验证 jsdom。

### CR-012 全局快捷键前后台语义错误，换绑操作不是事务性的

- `apps/desktop/src-tauri/src/shortcuts/mod.rs:53-64` 每次都 show/focus 并立即发 quick-create；前端 `mindmap-app.tsx:219-231` 无当前文档焦点判断。后台第一次按键可能直接建点，违反人工矩阵“第一次只唤醒”。
- `apps/desktop/src-tauri/src/shortcuts/mod.rs:101-126` 注册新键前先移除旧键；新键冲突/解析失败会把原工作键一起丢掉。
- 偏好写入失败时 runtime 绑定已改变，错误返回与实际状态不一致；启动冲突也只记日志。
- 修复方向：事务式换绑或完整 rollback；显式前后台状态机；冲突保留旧键并在 UI 可见。

### CR-013 “整理节点”在 DAG、深链和大量孤立节点上不正确或不安全

- `packages/core/src/organize.ts:32-43` 在检查全局 visited 前先把 target 加为 child；菱形 DAG 的共享后代可被多个父节点重复布局。
- `packages/core/src/organize.ts:32-45,84-111` 使用递归 DFS/子树计算/放置；schema 允许 10,000 节点，深链可栈溢出。
- `packages/core/src/organize.ts:113-135` 会重复处理孤立节点并产生不必要的大偏移。
- 修复方向：显式构造单父 spanning forest，遍历改迭代式；加入 DAG merge、环、10k 链、全孤立节点测试。

### CR-014 偏好文件损坏可触发未处理 rejection，并被升级成全屏 fatal overlay

- `packages/ui/src/onboarding/onboarding-flow.tsx:36-45` 对 `preferences.load()` 只有 `.then`，没有恢复路径。
- `apps/desktop/src/app/error-boundary.tsx:47-50` 把 unhandled rejection 画成 fatal。
- 非关键偏好损坏不应让整个脑图工具不可用。应默认回到未完成 onboarding/默认偏好，显示可理解警告并允许重写。

### CR-015 导出尺寸守卫只覆盖 PNG；PDF 在守卫/try 之前已创建页面并嵌入字体

- `packages/export/src/scene.ts:210-215` 的尺寸守卫是 PNG 专用。
- `packages/export/src/render-pdf.ts:26-68` 在 `try` 之前创建 PDF、页面并嵌入字体；超大页面或字体错误会直接 reject，不能返回结构化错误。
- 修复方向：为每种格式定义前置尺寸/资源预算，并在任何大分配或 font embed 前 fail closed；错误不得留下部分文件。

### CR-016 总门禁与质量证据存在“假绿”和过度声明

- `scripts/quality/run-all.mjs:18-49` 的 `quality` 不包含 format、build、cargo test、clippy、a11y、真实 E2E、人工矩阵；`integration` 仅是 unit + boundary。
- `tests/e2e/macos/cases.mjs:23-55` 实际只有 E2E-01A、E2E-16；`scripts/quality/run-e2e-macos.sh:1-12` 却宣称覆盖 E2E-02/03/04/05/08/09。
- `docs/quality/mm-090-manual-matrix.md:8-39` 全部未勾选。
- `docs/quality/evidence/mm-090-macos-e2e.json` 记录的是旧 commit `bcadbe8` 且 dirty；证据索引仍把多个 AC 标为 verified。
- `launch-router/file-open/file-safety` 三个入口都路由到同一 service suite；对应三个 JSON 不能证明三条真实 E2E。
- `evidence-index.json` 还引用不存在的 `mm-090-macos-file-lifecycle.json`、`mm-090-performance.json`、`mm-090-network.json` 与缺失的 `ac-*.json` 聚合物。
- 修复方向：先把未经证实状态降为 BLOCKED/UNVERIFIED；门禁校验 case ID、当前 commit、clean 状态、artifact 存在性、人工矩阵完成度，禁止复制一份 suite 结果冒充多场景。

### CR-017 性能门禁没有测规格中的关键指标，包体和启动资源已出现高风险信号

- `scripts/quality/run-performance.mjs` 实际只测画布/dense，未测冷启动、RSS、保存、导出、安装包。
- 当前 Vite 构建约 45 MB 未压缩；三份字体资源约 8.3 MB、8.5 MB、24.7 MB，另有约 2.5 MB wasm 和大 JS chunk。
- `apps/desktop/src/app/ports.ts:95-114` 启动时立即加载三份字体与 wasm；`apps/desktop/src/App.tsx:12-28` 等全部资源完成才挂载应用，会直接影响冷启动和峰值内存。
- `docs/quality/evidence-index.json` 把 AC-12 标为 verified，但所引用的 `mm-090-performance.json` 不存在。
- 修复方向：以真实 release bundle 测 installer、cold/warm start、RSS、300 节点交互、保存和三格式导出；优先懒加载 export 资源或采用经 ADR 批准的字体子集策略。

## 5. 中优先问题（P2）

### CR-018 文件提交存在 TOCTOU，durability 证据也高于实际保证

- `apps/desktop/src-tauri/src/file/mod.rs:123-153` 先验证 token、后独立 rename；两者之间的外部写入仍可能被覆盖。
- `apps/desktop/src-tauri/src/file/commit.rs:50-60` 忽略目录 fsync 失败，属于 best effort；质量报告却描述为完整 durable。
- 需要明确产品承诺，或加强 compare/replace/identity 检查和 sync 阶段故障注入；证据措辞必须与实现一致。

### CR-019 基础静态质量未进入唯一门禁

- `pnpm format:check` 失败 45 个文件。
- `cargo clippy --all-targets -- -D warnings` 在 `apps/desktop/src-tauri/src/file/commit.rs:73-75` 失败。
- `docs/quality/mm-090-report.md:63` 声称 clippy clean，已与当前基线不一致。

### CR-020 许可证和桌面安全硬化尚不完整

- 当前许可证扫描只覆盖 JS 直接依赖，Cargo 依赖仍是人工缺口。
- `apps/desktop/src-tauri/tauri.conf.json:22-24` 的 CSP 为 `null`。本地优先应用仍应在发布前设定最小 CSP，降低 WebView 内容注入的后果面。
- 应在不改变联网/遥测边界的前提下补 Cargo license audit 与 CSP 回归。

### CR-021 版本与治理文档漂移

- `docs/quality/v1-quality-gates.md` 仍写 G1 pending，而 PRD/decision register 已批准。
- 根 AGENTS 仍描述“产品发现阶段”，实际已到 `v0.1.3` 实现与验收阶段。
- Git 标签为 `v0.1.3`，package/Tauri 仍为 `0.1.0`。是否同步需由发布策略决定，但不能在证据中混用。

## 6. 推荐处置顺序

1. **冻结发布结论**：现有证据保留作历史记录，但把当前 release verdict 设为 BLOCKED，不再以 `pnpm quality` 单独代表可发布。
2. **先修数据安全链**：CR-001 → CR-002 → CR-003。三项必须串行，先建立失败测试再改实现。
3. **再修生命周期与文件边界**：CR-004/005 → CR-006/007。多窗口不得与 dirty-close 分开验收。
4. **恢复导出与领域正确性**：CR-008/009/015、CR-013/014。
