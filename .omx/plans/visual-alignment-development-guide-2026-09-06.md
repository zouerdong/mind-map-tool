# 参考对齐开发行动指南

日期：2026-09-06。状态：后续工作建议，用户已授权审查与规划，本轮不执行产品改造。与 [任务卡](./visual-alignment-task-cards-2026-09-06.md)、[视觉增补](../product/visual-target-brief-2026-09-06.md)、[审查报告](./visual-alignment-audit-2026-09-06.md) 配套。

## 1. 最直接的路线

**先把 12 节点的参考工作态和“散乱→规整”做成可审阅的样式/动效原型，再实现同一个产品契约。** 不继续让每个功能 Agent 各自加按钮，最后才统一装修；也不换 Tauri/React Flow 或重写保存系统。

本批次有两条可并行的线：

- 视觉线：参考与状态 → 最小样式/几何契约 → 真实画布 → 协调动效 → 极简外壳 → 参考验收。
- 可靠性线：MRT-004W2R2 收口 → 不可信文件与偏好、焦点/热键整改 → 真实宿主集成 → 发布门禁与性能。

视觉原型、纯布局与共享几何不依赖原生多窗口完成；接入生产 App Shell 和宣称产品可交付仍依赖原生 Gate。下面的依赖是本批次建议，须在 VRA-000 启用时显式登记对旧“全部 UI 等 MRT-004”规则的替代。

## 4. 技术边界与推荐取舍

### 保留

- Tauri 2 宿主、React/TypeScript、React Flow 视图，已批 Noto Sans SC/LXGW WenKai，web-ts-wasm 三格式导出。
- `DocumentSession`/identity/保存快照/平台 port；整理提交一次 `MoveNodes`。
- 用户任意放置与自由连线；连线方向是层级输入，不建立强制单父树。
- React Flow attribution 的既有批准；参考未画署名不能作为隐藏授权。

### 修改

- 统一视觉解析、文本、节点轮廓、边路径、箭头与 bounds；优先扩充现有 `packages/export` 的共享契约，因为 UI/export 已是两个消费者。不另建杂项 utils 包。
- core 只拥有图、样式语义与命令；几何不得依赖 React Flow/DOM/Tauri。布局输出目标坐标，线的具体 path 由同源几何消费目标/显示坐标派生。
- DAG 分层使用全图信息，稳定排序与尺寸感知；环先做确定性降级再排列，不能删原边。可用强连通分量缩点与最长前驱层级，具体实现由 VRA-030 证明。先不新增布局依赖；若复杂度/性能证明需要，单独比较体积、许可、维护与替代后提 ADR。
- 样式应随文件保存、undo/redo；普通/强调不能混同 hover/selected。眉题为空时的节点仍自然，分类词完全由用户输入。字体、字号/runs、文本、眉题等几何变更必须用共享字体度量重测受影响节点，把内容/样式和权威 size 原子提交；不得在 renderer 中偷偷补尺寸。
- 动画由一个协调者产生显示坐标，所有画面元素使用它；端口侧、路由通道和控制点也必须连续，不能每帧离散切换导致线跳形。持久化保存的是已提交终态。拖动等普通交互不套全局位置 transition。

### 不扩大

本批次不增加账号、云、AI、模板库、视频演示系统、任意 CSS 样式编辑器、阶段分类、自由手工曲线编辑器、移动/Web 发布版或 Windows 首发。参考视频不要求重新建立演示功能。

## 6. 多 Agent 协作规则

1. 共享工作区先记录 HEAD 和 dirty 文件，不格式化整个仓库，不覆盖别人的生命周期改动。隔离 worktree 如需创建遵循项目 Git 红线，禁止擅自 push/rebase/reset。
2. 产品/契约 owner 先写 PRD 增补和 Proposed ADR，审阅后交 core 与 renderer。实现 Agent 不自行扩大字段枚举、依赖、文件版本。
3. VRA-020 的 schema/commands 与 VRA-030 的 organize 可以分开，但 `index.ts`、fixtures 与测试配置由指定整合 owner 串行修改。
4. VRA-040 拥有 `packages/export` 和共享几何；VRA-050 拥有 UI projection/node/edge/editor；VRA-060 拥有动画协调与接入点。接口冻结前不并行修改同一文件。
5. `mindmap-app.tsx` 由 VRA-070 整合 owner 修改；MRT-004W2R2 仍在改的生命周期处理不要混入 UI 重构。先抽取纯展示组件，保持 action/port 边界，再在 G-NATIVE 后接线。
6. 每张卡交付：改动文件、已满足验收、实际命令/exit code、当前截图/录像、未解决事项与下一卡接口。不接受只有“tests pass”的完成说明。
7. 新证据目录先写 README，限定合成数据、命名、生成命令、保留方式、owner；公开/打包资源另做来源许可登记。删除、迁移、系统配置与发布仍必须遵守用户红线。

## 8. 唯一验证入口与通过标准

优先使用根 README 的标准命令：`pnpm typecheck`、`pnpm lint`、`pnpm test:unit`、`pnpm build`。结构性实现卡还需相关 scoped tests、`pnpm test:export`、`pnpm test:a11y`、`pnpm quality` 的适用部分以及架构边界检查；不能跳过既有失败。新视觉/动效 runner 由 VRA-080 实现并交 MRT-010 接入，**实现前不把臆造的脚本名写作已可运行命令**。

文档卡只需对账、链接/哈希/格式与 diff 检查。UI 动效必须有真实 RF 浏览器证据；字体、保存、系统焦点与生命周期必须有真 macOS Tauri 证据。Windows 本轮写移植说明，未测项明确 `not-run`，不借 macOS 结果声称双平台通过。

每张卡的独立评审可以给 PASS / NEEDS-REMEDIATION / BLOCKED（缺外部前提），不能以漂亮截图覆盖数据错误，也不能因不相关的原生缺口阻止已解耦的参考原型前进。
