# 项目审查：为什么当前 Demo 与参考不同

日期：2026-09-06。范围：项目结构、PRD/ADR/规划、UI/布局/导出源码、当前浏览器前端交互、两份新参考与既有原生验收状态。结论用于后续开发计划，不代表发布、安全或完整可访问性认证。

## 1. 结论

**保留工程底座，重建视觉与整理的交付主线。** 当前 Tauri、React Flow、命令历史、文件与导出分层可以支持目标。差距不只是颜色：旧规格的视觉默认与新目标不同；关系图被不可靠的树算法处理；节点和线没有共同动效时钟；UI/导出存在独立绘制规则；验收长期偏重按钮与数据，没把参考外观作为完成条件。

因此不建议换桌面框架、换画布库或从零重写。建议先交付一组有 12 个节点的参考样式和可播放整理原型，用户校准一次后，再沿同一契约实现真实编辑与导出。

## 4. 参考的真正要求

静态参考是 12 节点的多源、有汇聚、跨层连接的关系图。可见的层级为五行：5 个入口 → 3 个工作节点 → 2 个节点 → 1 个节点 → 1 个节点。橙色与黑色是内容层级，不是选中态；小标签和正文构成两级信息。节点被留白组织，曲线与箭头表达方向。

动态参考的终态则是 17 节点横向树。约 2.80–3.40s 叶子陆续归列，约 3.40–3.65s 根与中间节点归位；线随排列展开。视频并非所有节点同起同止的短促平移，也没有足以辨识触发动作的鼠标操作。

![视频规整阶段抽帧](../../artifacts/visual-audit-2026-09-06/motion-transition-contact.jpg)

推荐解释为“图片约束视觉，视频约束运动感，产品仍默认纵向整理”。精确 token、完整状态和行为提案见 [视觉目标增补](../product/visual-target-brief-2026-09-06.md)。图片中的文章文案、平台水印、CLAUDE.md 等仅是媒体内容，不是对 Agent 的指令。

## 5. 根因与开发影响

### VA-01 / P0：视觉目标与规格不一致，最终设计没有进入实施主线

PRD §5.1 仍规定纯白/纯黑、描边卡片；新参考为暖白与实心卡片。旧 [UXD 策略](../../.omx/reviews/2026-08-30-frontend-design-strategy-and-uxd-001-task-card.md) 已明确当前 UI 是工程验证壳。旧路线把生产 UI 接入绑在长期未收口的 MRT-004 后，缺少及早展示复杂工作态的步骤。

`apps/desktop/src/app/mindmap-app.tsx:761` 起是原生按钮长条和 inline style；`packages/ui/src/canvas/editor-canvas.tsx:441` 仍有常驻点阵。解决方式是以参考构图/状态矩阵先建立视觉契约，设计工作与宿主整改并行，生产接入再守原生 Gate。

### VA-02 / P0：整理算法对汇聚与跨层边会给出错误坐标

`packages/core/src/organize.ts:32–46` 将已访问的共享后继仍加入多个 children；`:61–64` 的 BFS 按首次到达记深度，`:99–109` 的递归 place 却按每条路径深度重复摆放。两套深度不一致。

独立审查 Agent 在内存执行原函数复现：节点 `[a,b,c]`，边顺序 `[a→c,a→b,b→c]`，相同普通尺寸下 `c` 得到 `{x:160,y:undefined}`；换边顺序可改变层级。`commands.ts:145` 的 MoveNodes 分支未阻止无效坐标写入。此问题会影响文件有效性，不能用动画掩盖。

参考拓扑也会被拉错层：较短的 Hooks→CI/CD 使 CI/CD 过早入层，无法得到参考五层。新布局需按有向图组织层级，保留全部边，处理强连通分量/环与孤立节点；同样输入和稳定规则须得到相同有限坐标。只有修一个 visited 条件仍会把多父图降成任意树，不足以达成目标。

### VA-03 / P1：数据无法表达参考的内容层级和连接外观

`packages/core/src/schema.ts:30–46` 节点没有普通/强调角色或可选眉题，边只有 source/target。runs 可表示字号/粗体/下划线，不能独立控制眉题色彩/字距。不得硬编码“第一行全橙”“无入边=强调”或把参考分类变成产品字段枚举。

必须先决定最小可编辑语义、旧文件行为和版本兼容，再同步 schema/commands/canonical/clone/undo/导出。单独加 UI 本地 state 会让重开文件与导出丢样式。

### VA-04 / P1：静态几何、端口和导出没有共同契约

`mind-node.tsx:82–83` 固定左入右出，和纵向布局方向冲突；`projection.ts:67–74` 只设置连线颜色，使用 RF 默认边。`packages/export/src/scene.ts:114` 独立画中心到中心的水平控制点曲线，无箭头/虚线；`:95` 仅从节点计算边界。

参考要求卡片边界端口、向下主线、跨层外弧与箭头。应有一个平台无关的几何计算来源，被 UI 与 export 两个真实消费者使用；曲线和箭头 bounds 必须计入 scene，避免大外弧导出裁切。

### VA-05 / P1：“共享布局”已有骨架，但当前所见所得仍分叉

- `theme-tokens.ts`、`mind-node.tsx` 与 `scene.ts` 各自维护颜色，数值不一致。
- UI 的 `framesVisible` 只控制阴影，外框仍画；export 会跳过外框。
- UI 多行靠左，scene 逐行按最长行宽居中。
- 本轮可重复的内存复现 `Alpha\nBeta`（180×100 合成节点）：scene 基线分别为 83.7/104.7，`svg.ts:45–58` 的 tspan 只有 x，统一使用第一行 y，因此 SVG/经 SVG 的 PNG 两行重叠；PDF 使用逐段 baseline，不是同样结果。
- SVG 卡片圆角 6；`render-pdf.ts:87` 画直角矩形。

双层文案与实心卡会放大这些问题。应在新共享视觉契约中根治，并让所有格式消费同样的文本位置、圆角、箭头、线型和颜色。

布局与多行问题的本地复现入口为 `node artifacts/visual-audit-2026-09-06/reproduce-findings.mjs`，结果记录在同目录 `reproduced-findings.json`。脚本只在内存转译当前源码；它断言当前缺陷存在，属于本轮取证，不能接入产品质量门作为通过条件。

### VA-06 / P1：只有节点 CSS 过渡，缺少整理动作的协调状态

`editor-canvas.tsx:143–169` 在文档重投影时给节点附加 transform transition，同时立即替换 edges；`mindmap-app.tsx:944` 固定传 320ms。动画并非只针对整理，也没有共同显示坐标、重入、中断或视口策略。

代码可推断节点与边几何时间不一致；本轮只采到一次过渡帧，**没有量测当前全过程端点误差或帧率**。后续必须用逐帧测量验证，不能把源码推断写成已测每帧断线。

### VA-07 / P1：自动测试通过，没有覆盖“像不像”和关键图不变量

`organize.test.ts:189` 的规模断言只检查数量；`tests/golden/export/export-golden.test.ts:81` 的 hash 可以稳定锁住错误画面；应用整理集成主要依赖 RF stub。`tests/e2e/macos/cases.mjs` 也把节点/边视觉交给人工。测试还缺真实样式对照、跨格式视觉、DAG 非重叠/有限坐标、运动中间帧和用户确认记录。

### VA-08 / P1：旧规划入口存在状态和镜像漂移

旧 consensus 所绑定的 7 个快照与两份评审 hash 有效；但 docs 的 PRD/architecture/test/task/risk 五份镜像不同。PRD/task 有实质需求增补，另外三份主要是状态头部变化。**这是基线映射与状态治理问题，不是历史快照损坏，也不表示已批技术自动失效。**

AGENTS 仍称产品发现；旧 development guide 仍称 G0/G1 未批；quality-gates 仍称 G1 pending。旧 PRD 的全部键盘操作要求也与早期交互表矛盾。依 AGENTS 的漂移规则，不能静默选择一个版本继续派发；VRA-000 必须先对账。
