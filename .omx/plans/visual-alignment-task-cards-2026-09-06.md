# 参考对齐任务卡（VRA 批次）

日期：2026-09-06。与 [行动指南](./visual-alignment-development-guide-2026-09-06.md)、[视觉目标](../product/visual-target-brief-2026-09-06.md) 配套。共 10 个工作包；**不是十张可无条件同时执行的卡**。本轮只交付审查与计划，实施由后续获授权的 Agent 完成。

## 通用执行契约

- 先核对 `.omx/plans/visual-alignment-review-manifest-2026-09-06.json` 与本批镜像；不匹配则停派发并重新审阅。
- 遵守 AGENTS/目录 README；记录当前 HEAD、dirty 文件、任务允许范围。禁止覆盖他人变更、全库格式化、删除、推送、改凭据/系统配置或发布。
- 大改动先展示本卡目标、预计文件、风险、验证方式，并确认用户已批准相应 Plan。已批准的卡无需对日常可逆实现反复询问。
- 所有新增产品字段、schema 兼容、依赖等先写 PRD/Proposed ADR，不能从本规划的建议措辞自行升级为 Accepted。
- 通用完成包：改动清单、验收逐条结果、实际命令与退出码、合成数据的截图/录影/路径、失败/未测项、给下一卡的接口；独立 Agent 审查后才能标完成。
- 文档卡不要求无关全库测试；实现卡按根 README 跑 typecheck/lint/test:unit/build 及本卡风险所需检查。视觉/动画证据不得来自 RF stub 或旧截图。

## VRA-000：对齐规划基线与任务所有权

**类型/优先级**：文档治理，P0。**状态**：可执行（仅规划对账），不依赖 MRT-004。**目标**：后续 Agent 知道哪个决定已批、哪个是假设、旧问题由谁处理。

**输入/阅读**：AGENTS、根 README、docs 各目录 README；旧 `.omx/plans/ralplan-consensus-minimal-mind-map-tool.json`；decision-register/G1/ADR 0008 独立批准；旧 MRT/UXD/UXI 卡及其最新验收；本批四份文档。

**允许范围**：AGENTS/README 的已知状态说明、docs/product/planning/quality 的状态与映射、新审阅记录和 manifest。不得修改产品代码、Accepted ADR 正文/hash、schema、CI/生产配置。

**步骤**：

1. 验证旧 7 个快照和两份审查 hash；逐一比较 PRD/architecture/test/task/risk 五份 docs 镜像，区分头部差异、已有批准增补和未决冲突。

3. 将 PRD 的键盘表、主动整理/不强制树结构、全局唤起等冲突列成具体条款，已有批准可据证据对齐，找不到证据则列待决，禁止猜测。

5. 生成新的审阅快照/manifest；本批草案经过同伴 review 不等于用户批准，必须分别记录。

**验收**：所有旧差异都有结论或具体隔离项；每个旧未完成问题恰有一个 owner；无 hash 静默失效；新入口链接可达，镜像精确匹配新快照。无法判断的批准不阻止报告产出，但相关实现卡不得解锁。

**下一步**：G-BASE 后派 VRA-010；原生负责人继续 W2R2。证据冲突仍待用户判断时，先展示冲突与推荐，不要求重新审所有已批技术。

## VRA-010：同一参考方向的完整视觉与运动契约

**类型/优先级**：设计/可逆原型，P0。**依赖**：VRA-000；用户派发本卡并批准原型范围。生产改造需 G-PLAN，具体视觉/语义需 G-VIS。

**目标**：让用户在真实工作态确认“这次方向对了”，并产出可直接实现的规格。不是再做 2–3 套无关风格，也不是只画空白主页。

**允许范围**：docs/product 的 brief/state/tokens/motion 增补、docs/decisions 下 Proposed ADR、tests 的合成参考夹具、受规则约束的本地隔离原型。不得重写生产 `MindMapApp`、调用真实文件保存、修改 Rust host、引入新 runtime dependency。

**交付**：

1. 固定 `reference-dag-12`：用自写文本复用参考拓扑；一份参考坐标版只验外观，一份散乱坐标版供算法使用；分别注明用途，不拿手工坐标冒充算法。
2. 同一方向的暖白/黑板工作态，单选/多选/键盘焦点、编辑/IME、连线、文件/导出、保存冲突、关闭三分支、引导状态；至少覆盖 800×600 与 1280×800 窗口。
3. 规整动效原型：默认纵向布局借用 MOV 收束节奏，主时长以 800ms 起调；完整录像与关键帧、打断策略、reduced-motion。可用 fixture 驱动，但明确尚非生产历史/文件集成。
4. token 表：精确色值、字体、尺寸、圆角、留白、文本基线、连线/箭头、选中/焦点；所有偏离参考的点有原因。
5. D1–D6 一次决策包：推荐暖白/实心卡、人工强调、可选眉题、实/虚线、默认箭头、不加层号/分类系统；给出黑板方案、旧文档视觉保留和文件兼容方向。

**验收**：参考与同内容原型并排；12 节点复杂工作态可读，英文与中文都成立；无水印/参考文案硬编码；状态矩阵无空项；用户明确确认 G-VIS 或给出具体修改。用户本轮已经选定审美方向，评审只校准实现，不强制再次选风格。

**停止条件**：新增字体/布局库/展示模式/数据语义超出 D1–D6 时，先给成本与提案，不顺便实施。

## VRA-020：最小样式模型与文件兼容

**类型/优先级**：core/文件契约，P0。**依赖**：G-PLAN、G-VIS；实现前 G-SCHEMA。与 MRT-005 指定同一 schema/commands 整合 owner。

**目标**：普通/强调、可选眉题、边外观在编辑、undo、保存、重开与导出中不丢失；保护现有用户文件。

**预计范围**：`packages/core/src/schema.ts`、`commands.ts`、`canonical.ts`、`index.ts` 及相邻测试/fixtures；必要的保存/解码契约测试。正式条款先写 docs/product 与新 Proposed ADR，不能直接改已有 Accepted ADR 绑定内容。

**步骤/契约**：

- 将 G-VIS 选项变成最小字段与默认值；如果眉题被精简则不预埋无消费者字段。禁止任意 CSS 字符串或参考业务分类枚举。
- 明确新写 schemaVersion、旧版读取、未知未来版本拒绝、缺省值、canonical 顺序/精度、旧文件视觉样式与 node size 策略。不得在加载时静默改旧坐标/尺寸；兼容转换如何影响 dirty/保存提示写明。
- 如需内存转换，写纯转换并保留原文件；新写版本的保存必须走已批文件协议。任何批量迁移另需用户批准，不在卡内执行。
- 属性修改进入单条可撤销命令；删除恢复/克隆/文本编辑/分叉 undo 均保留新字段。当前 `MoveNodes` 和所有创建/编辑路径验证 finite、范围与正尺寸，拒绝非法命令时文档与历史不变。
- 文本、眉题、font、字号/runs、视觉 profile 等影响几何的编辑必须用 VRA-040 同源 FontResolver 重测全部受影响节点，并将内容/样式与权威 size 原子提交为同一条历史，任何一项失败不得部分提交。文档换字体不能只换 token 留旧尺寸；core 不引入字体库/DOM。本卡以注入已测尺寸的纯测试验收命令接口，不等待 VRA-040；真实测量/编辑联调由 VRA-040/050 负责，不形成反向依赖。
- 样式 token 存语义，不存 UI 选择态、路径缓存、动画进度、viewport。是否增加文档外观版本/profile 由 ADR 的旧文件策略决定，不由 renderer 偷改默认。

**必测**：v1 文件读取不丢内容、旧版与新版本 save/open roundtrip；未知/非法字段；样式 undo/redo、分叉 dirty、in-flight save；新字段删除恢复；无效坐标/尺寸拒绝；换字体/改字号/眉题后 size 原子更新并可一次撤销；中英文/多行/runs 混合。不能只测 happy path。

**验收**：批准 ADR/PRD、完整兼容矩阵、schema/commands/canonical 测试与标准检查通过；没有在真实用户目录执行转换或写文件。

## VRA-030：支持汇聚与跨层的规整布局

**类型/优先级**：平台无关算法，P0。**依赖**：G-BASE、G-PLAN、VRA-010 的布局契约冻结；可与 VRA-020 在隔离文件范围并行，合并前对齐新尺寸契约。吸收 MRT-007 整理子项。

**预计范围**：`packages/core/src/organize.ts`、`organize.test.ts`、必要的单一职责布局模块与合成 fixtures；不改 UI、文件 port、偏好恢复或 renderer。

**目标/规则**：

- 用全图建立稳定层级；对于无环部分，每条参与层级的 source→target 满足 target 层级严格靠后，短跨层边不能把目标拉回。
- 多父节点只放一次；同层节点按稳定规则排序，计算真实尺寸与间距；参考 DAG 有合理五层节奏，跨层关系保留。
- 环用确定性规则降级（推荐 SCC 缩点后分层）；反馈边标为布局内部信息，原文档边不删除、不翻向。孤立节点独立编组，不因遍历副作用跑到极远处。建议右侧紧邻主图成列、第一项顶齐第一层；参考中那个孤立节点因此仍在顶排。多个孤立节点不强求复制五行构图，G-VIS 明确这种有意差异。
- 先建立邻接/入度索引，避免每个 DFS 节点都扫描全部边；不建立指数递归子树。输出只包含有限、合法目标坐标。
- `organizeCommand` 仍只返回一条 `MoveNodes`；布局不改 text/runs/样式/size/边，不改 viewport；已整理再次触发为 no-op。
- 对外结果必须区分成功、no-op 和结构化失败；如 10,000 节点单链/超长大节点的合法文档无法在现有坐标上限内放下，返回具体超限错误而不是非法坐标。失败时 document/history 不变，UI 不得报整理成功；必要的返回类型调整须同步调用方与测试。
- 稳定性定义写清：同文档同结果；不依赖当前散乱坐标；节点顺序可作为显式同层 tie-break，但边数组置换不得产生不同层级或无效坐标。

**必测反例**：`a→c,a→b,b→c` 及全部边顺序；diamond；多个根汇聚；12 节点/13 边参考 DAG；环/双向边/无边/单节点/负起始坐标；长中文与不同节点尺寸；300/450；10,000 节点单链避免栈溢出，无法合法安置则按上述结构化失败验收，不降低现有边界。

**验收**：每个节点恰好一次，坐标 finite 且合法；无节点矩形重叠；层级约束/孤立策略通过；原边完整；第二次 no-op；一次 undo 恢复全部旧坐标。附终态图及布局用时，不只检查 Map.size。

**停止条件**：若自研受控范围不能达标，提交布局依赖对照与 ADR，不能自行安装库或降级成丢多父关系的树。

## VRA-040：UI 与三格式导出的共同绘制契约

**类型/优先级**：shared geometry/export，P0。**依赖**：VRA-020、VRA-010；VRA-030 输出接口稳定。承接 MRT-006 的视觉一致性，剩余字体失败/资源上限等逐项保留到完成。

**预计范围**：`packages/export/src/layout.ts`、`scene.ts`、`svg.ts`、`render-png.ts`、`render-pdf.ts`，必要的 `visual-style.ts`/`edge-geometry.ts` 等单一职责模块；相关 export/golden 测试。与 UI owner 先冻结导出接口。

**交付契约**：

- 一处解析文档主题、节点角色/眉题、文本 runs、框形与 frame visibility；UI/export 消费相同颜色、文本段坐标、圆角、padding、baseline 和 size，不再各有一套常数。暴露完整节点测量函数供 VRA-020/050 的几何编辑事务使用，渲染不能静默改持久化尺寸。
- 一处派生边界端点、方向、控制点/路径段、箭头与线型。纵向主边底出顶入，汇聚边分配端口，跨层外弧避开无关卡片；自由拖动时合理调整端口，算法可重复。
- UI 消费当前显示坐标；导出消费 canonical 目标坐标；相同静态输入输出完全相同几何。PDF 要从共同 primitives 绘制，不另猜曲线或圆角。
- 动画所需的端口侧/路由通道/控制点拓扑一并交付：同一次动作冻结路线拓扑后插值，或提供经验证的连续过渡；禁止每帧离散重选路径而使线条瞬间跳形。
- scene bounds 包含卡片、文字、曲线极值、箭头和描边留白；负坐标与外侧大弧不裁切。
- 修复多行 `<tspan>` 没有各自 y/baseline、UI/scene 对齐差、frame visibility 与 PDF 直角等已确认分叉；保持 SVG 语义文本、无 foreignObject、真实内嵌字体与确定性。

**必测/证据**：两行 `Alpha\nBeta` 和中文眉题+正文必须逐行可见；长跨层箭头、实虚线、圆角、frames off、dark、两字体/粗体/下划线；UI 期望几何、SVG/2x PNG/PDF 四方对照。SVG 相同输入 hash 不变；PNG 尺寸各轴 2×；bounds 全包含。缺字按已批 ADR 0005 的可见替代/警告保持确定性；缺字体资源、空文档、尺寸超限按既有错误契约可控失败，改变缺字政策需另批。

**验收**：相关标准检查与 `pnpm test:export` 通过，真实渲染各格式并人工查看；更新 golden 之前先给差异图和预期理由，禁止“重生成 hash 即修复”的假绿。保持既定包边界，无 DOM 截图导出。

## VRA-050：参考画布、节点与真实编辑操作面

**类型/优先级**：UI，P0。**依赖**：VRA-020/040 与 G-VIS；消费 MRT-008 焦点/快捷键契约。原生热键状态机未完成时可在隔离 browser fixture 验证，不宣称 native 完成。吸收 MRT-009。

**预计范围**：`packages/ui/src/projection/projection.ts`、`canvas/mind-node.tsx`、`node-text-editor.tsx`、`editor-canvas.tsx`、`theme/`、controller 及相邻测试；由单一 owner 调整 UI exports。保留 app/host action 边界。

**目标**：暖白留白、实心卡片、双层文案、明确的关系曲线和箭头出现在真实 RF 画布，能继续自由创建、编辑、连线，而非静态截图。

**步骤**：

1. 用 VRA-040 同源契约绘制卡片/文本/边；清理冲突的旧 token 消费，默认移除点阵视觉而非隐藏交互画布；保留 attribution。
2. 节点创建直达正文输入；眉题有可发现但不抢焦点的入口；选中、hover、连接候选、键盘 focus 不互相冒充。端口默认弱化，hover/focus/连线时可发现，键盘也能连线。
3. 补全已有 P0：局部字号/粗体/下划线、两字体、每节点形状、frame visibility；新增角色/边线型只按 G-VIS。所有修改进入既有命令系统，不存额外 UI-only 样式。
4. 处理 IME 组合、选区、文本 runs 编辑变更、失焦提交/取消、size 测量；不得把改一个字变成清空全部格式。所有影响几何的文本/眉题/字体/字号操作用共享 FontResolver 重测，将内容/样式和 size 在同一命令原子提交；批量换字体涵盖全部受影响节点且只产生一条逻辑命令。
5. 给 VRA-060 留出明确 motion coordinator 接口，不继续全局 CSS transform 动画；给 VRA-070 留出外壳 action/selection/context callbacks。

**验收**：12 节点真 RF 截图与 G-VIS 同内容对照；单/多选/编辑/连接/暗色/帧隐藏状态全部有证据；实际中文 IME 手测；键盘完成核心流程；`pnpm test:a11y` 加人工焦点检查；pan/zoom 不 dirty，内容样式 dirty/undo 正确。

## VRA-060：一条整理动作的节点、线与视口动画

**类型/优先级**：交互动画，P0。**依赖**：VRA-030/040/050，VRA-010 运动契约。**预计范围**：`packages/ui/src/canvas/` 的单一动画协调模块、EditorCanvas 接口和 motion 测试；应用接线由 VRA-070 owner 串行整合。

**目标**：连续看得懂的散乱→规整，节点/线/箭头共同运动、可撤销、可打断，不丢数据、不跳镜头。

**实现约束**：

- 以 `from / to / startTime / duration / per-node-delay / phase` 等明确 view state 管理一次过渡；一个 requestAnimationFrame 时钟。具体字段可变，职责不可散落多个 effects。
- canonical 终态通过一次 `MoveNodes` 提交；每帧只改显示坐标，边和箭头从相同显示坐标计算，禁止节点 CSS 延迟而边直接跳终点。
- 端口侧、路由通道、控制点必须连续衔接；冻结路线拓扑后插值或使用经验证的连续方案，不能仅用“端点≤1px”证明中段曲线没有跳形。
- 时间线采用 G-VIS 校准值；普通拖动/编辑不要误用整理过渡。开始、中途、完成、取消有明确状态，卸载/文档切换后不会用旧计时器写新会话。
- 明确并测试重入：重复整理 no-op；连续不同布局、undo/redo 从当前显示态接续；拖动/连线接管；编辑未提交与 IME；保存/导出使用 canonical 终态；关闭/新建保持既有安全协议。
- 视口前后边界并集+安全边距，只做一次协调，不每帧 fitView；能保持视口时保持，不把一个小节点放大至 maxZoom。用户主动 pan/zoom 时交还控制。
- reduced-motion 全链路归零；后台页恢复不重播长动画；300/450 不通过隐藏内容取巧，必要时取消错峰/简化路径并在原型中确认视觉降级。
